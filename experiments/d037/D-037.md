# D-037 Ω — online receipt index vs batch ledger vs native compaction

Record style: PR-template (what & why / what re-grounds it). No D-036 in this branch; nothing mirrored.
Status: SEALED (hashes at end). Verdicts appended after scoring, never edited above the seal line.

## What & why

**Claim C-037.** On a serial task chain forcing ≥2 auto-compactions, a bounded index partition written online from execution receipts and read at every prompt under a fixed budget preserves cross-compaction dependency recall better than native compaction and better than a batch ledger written only at PreCompact.

**Falsifier.** If arm C does not beat arm B on presence π̂ (defined below) by ≥ 0.15, the online loop is not the mechanism and the next Plateau iteration is ledger-at-compaction.

**Arms** (isolated worktrees, identical chain, identical model, identical `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=40`):
- **A vanilla** — no hooks.
- **B batch ledger** — `settings.arm_B.json`: `ledger.py` at PreCompact rebuilds the store from the transcript; `inject.py` at SessionStart(compact) only, budget 6000 chars.
- **C online loop (Ω)** — `settings.arm_omega.json`: `receipt.py` on every PostToolUse, `snapshot.py` at PreCompact, `inject.py` at SessionStart(compact) with 6000 chars and at UserPromptSubmit with 1200 chars, `CLAUDE.md.snippet` appended to the worktree's CLAUDE.md so the worker knows `lookup.py` exists. Registered confound: B and C differ in write cadence *and* read cadence; the object of test is the online loop as a whole.

Budget for the headline run: `D037_BUDGET_CHARS=1500` at compaction for both B and C (forces eviction; the 6000 setting is the capacity-safe control, run it only if the 1500 result is ambiguous).

**Chain.** Generate `d037_target/`: 6 Python modules, small pytest suite, and a fixture `FIXTURE.md` of ~15 000 tokens. **N = 13** tasks. Every task begins "Read d037_target/FIXTURE.md fully." Task k requires a fact the worker itself established in task k−3 (a constant name, a function name, a file location it chose); the generator writes each task prompt plus a deterministic AST/string check for "used the k−3 fact". Each task must define **≥ 4 symbols** (distractors) so the selector is actually exercised at 1500 chars. Tasks run as one continuing session per arm per run: first `claude -p "<task1>"`, then `claude -p "<task k>" --continue`. Straddling tasks (a compaction boundary in [k−3, k−1]) with m = 5 are k ∈ {6,7,8,11,12,13}; non-straddling measured tasks are k ∈ {4,5,9,10}.

**Compaction is a controlled variable.** With window ≈ 200k, threshold 0.40 and S = 1500 tokens, θW ≈ 79 400. Preflight measures the residual r per task once from the transcript usage fields; set fixture size so that g = F + r ≈ 15 900 → m = 5. Do not "add reads until it compacts".

### Metrics and estimators (scored by a separate process on sealed bytes, `--disallowedTools "*"`, every scored item cites its transcript line)

Per arm and run, split tasks into straddling (S) and non-straddling (NS):
- R_X^S, R_X^NS = fraction of tasks in each set where the k−3 fact is used correctly.
- α̂ = R_A^NS (use-probability: the model acts on a fact that is present)
- λ̂ = 1 − R_A^S / α̂ (native compaction loss)
- π̂_X = 1 − (1 − R_X^S / α̂) / λ̂ for X ∈ {B, C} (presence in the index)
- ρ̂ = injected chars/4 ÷ total output tokens (arm C)
- re-derivation count: files re-opened after a compaction that were read before it
- tokens per task from transcript usage fields, not hook payloads

### Pre-registered bets

| Bet | Statement | P |
|---|---|---|
| B1 | R_C^S > R_A^S | 0.85 |
| B2 | π̂_C − π̂_B ≥ 0.15 (the only discriminating bet) | 0.50 |
| B3 | R_B^S > R_A^S | 0.80 |
| B4 | ρ̂ < 0.05 | 0.85 |
| B5 | tokens/task_C ≤ tokens/task_A | 0.55 |

3 runs per arm, different chain seeds. WIN = holds in ≥2 of 3; PARTIAL = holds in 2 of 3 with π̂ gap < 0.15 or R margin < 0.05; LOSS otherwise. B2 LOSS ⇒ conclusion line: "online loop not supported; next iteration = ledger-at-compaction".

### Spend gate and kill criteria

Hard cap 9 sessions (3×3) plus ≤3 preflight sessions. Kill and mark VOID if a worker dies in <5 s (preserve raw). Mark CONFOUNDED and do not score if any arm sees <2 compactions or any injection exceeds its budget. Raw transcripts and `.d037/hooks.log` per arm/run under `experiments/d037/raw/<arm>/<run>/`, never overwritten.
