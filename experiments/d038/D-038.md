# D-038 — does a compaction bridge carry attention across a real multi-epic task? (WaveX concierge agent)

Record style: PR-template (what & why / what re-grounds it), as D-037. Status: **DRAFT — NOT SEALED.** No worker or
judge session has run; the only executions so far are offline (extractor dry-run on D-037's sealed transcripts,
synthetic scorer run, worktree assembly + gate on the pinned target). Verdicts are appended after scoring, never edited
above the seal line.

Lineage. D-037 Ω resolved all five bets LOSS with λ̂ = 0 in 3/3 runs: on a 13-task synthetic chain, names the worker
wrote itself did not decay under native compaction, so no index could show a gain. That design measures a ceiling.
D-038 does not re-run it on a real subtree; it changes what is measured: **decay of facts the worker discovered or
decided during a real multi-epic production task**, probed at increasing distance, with a complexity gate that voids
the run if native compaction shows no decay at all.

## What & why

**Claim C-038.** On a real multi-epic production task in `scripts/concierge-agent`, (i) a vanilla session shows
measurable attention decay: probe recall of *discovered* facts falls with tokens-since-fact and compactions crossed;
(ii) the bridge arm's recall curve dominates vanilla's; (iii) the bridge re-derives less; (iv) task quality is not lower.

**Complexity gate.** If arm A's probe recall never drops below 0.70 in a far-lag bucket (≥ 1 compaction crossed, or
> 60 k tokens since the fact), the run is VOID: task below threshold, arms not scored. Conclusion line: "task below
decay threshold; increase horizon before testing the bridge again".

**Mechanism falsifier.** Gate passes and AUC_C − AUC_A < 0.10 ⇒ "bridge does not carry attention across compaction;
value limited to re-derivation savings".

### Decay probes (`probes.py`)

Between task turns the driver inserts probe turns: "Answer in one line, no tools, from memory only. …" about a fact
the worker **discovered or decided** earlier, taken mechanically from its own tool results in the transcript:
- **read** — a function's parameter list or the environment keys a file reads (from Read results of code files), or
  the file:line of the first hit of an earlier search (from Grep results);
- **exec** — a failed test's name, a summary count (`N passed`, `# fail N`, `N vulnerabilities`), the first error
  line, or "was this command blocked?" (from Bash results);
- **decided** — the name the worker gave a new class / function / constant (hinted by its value, parent or first
  body line, never by the name), or the path of a file it created (hinted by the file's first line).

A fact whose expected answer occurs in any task prompt is dictated, not discovered, and is dropped (whole-token
match). Each fact is probed once. Probes run on **forked sessions** (`--resume <sid> --fork-session`, all tools
disallowed) so the main session never sees the question; the driver records `probe_contaminates = true` only if run
with `--probe-mode inline`. Per probe the log carries class, kind, tokens since the fact last entered the context,
compactions crossed, the lag bucket (0–20 k / 20–60 k / > 60 k) and the compaction bucket (0 / 1 / ≥ 2), the answer,
the fork's session id and cost. Target ≥ 30 probes per run across the buckets; the scheduler (A17) holds each fact back
until it reaches a pre-assigned target lag bucket so that the far buckets are populated, and sweeps the remainder on
the last turn. Both arms use the same extractor over their own transcript (A16); arm C's receipt store is not the probe
source, so the probe sets are built identically.

### Judge (`judge_prompt.md`, `judge.py`)

Separate session per worktree, blind, read-only (`--allowedTools "Read,Grep,Glob,Bash(git diff:*),Bash(git log:*),
Bash(node --check:*),Bash(npm test:*),Bash(bash gate.sh:*)"`), cites a line for every score. It sees a **judge view**:
the worktree without `.claude/`, `.d037/` and `CLAUDE.md` (those paths are also git-ignored in the worktree, so no
commit carries them), the turn script, and `probes_blind.jsonl` (`id, turn_id, cls, q, expected, answer` only).
Decay: probe answers exact / fuzzy / wrong. Task: per epic 0–3, security items closed, runner green, one paragraph of
defects. Re-derivations and tokens/turn come from the scorer, not the judge.

### Metrics (`score.py`, deterministic over the judged raw)

- recall = mean over graded probes of exact = 1, fuzzy = 0.5, wrong = 0; reported per lag bucket, per compaction
  bucket and per class, per arm and run.
- AUC over the three lag buckets = (r₀ + 2 r₁ + r₂) / 4 (trapezoid, equal spacing); undefined if a bucket is empty.
- far-lag recall = recall over probes with lag bucket > 60 k **or** ≥ 1 compaction crossed (the gate reads this).
- re-derivations = Reads, after a compaction, of a target file that was Read before it (D-037 definition, main
  transcript only); tokens/turn = mean over task turns of input + cache-creation + output tokens; task score = sum of
  the judge's four epic scores.

`experiments/d038/raw/<run>/<token>/` (gitignored); the tarball is hashed into the record.
