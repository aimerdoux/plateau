# D-038 — ledger-at-compaction on a real server subtree (WaveX concierge agent)

Record style: PR-template (what & why / what re-grounds it), as D-037. Status: **DRAFT — NOT SEALED.** No worker
session has run and no tokens have been spent on this record; the only executions so far are offline (self-test,
dry-run gate). Verdicts are appended after scoring, never edited above the seal line.

Lineage. D-037 Ω resolved all five bets LOSS with λ̂ = 0 in 3/3 runs on a synthetic 6-module Python package: native
compaction lost no worker-established fact, so no index could show a gain. Its pre-registered conclusion line was
"online loop not supported; next iteration = ledger-at-compaction". D-038 is that iteration, with one deliberate move:
the target is a real, private Node.js server subtree instead of a generated package.

## What & why

**Claim C-038 (two-stage).** On a serial task chain over a real server subtree forcing ≥2 auto-compactions,
(i) native compaction loses a measurable share of worker-established k−3 facts (λ̂ > 0), and (ii) a batch ledger
written at PreCompact and injected at SessionStart(compact) under a fixed 1500-char budget restores part of what is
lost (π̂_B > 0, R_B^S > R_A^S).

**Falsifier.** Stage (i): if λ̂ < 0.10 in ≥2 of 3 runs, native compaction on Claude Code 2.1.273 / claude-sonnet-5 does
not lose worker-chosen names on a ~1.4k-line real subtree at N = 18, and the "compaction loses facts" premise that
motivates both the online loop (D-037) and the ledger has no observed problem to solve at this scale. Stage (ii): if
λ̂ ≥ 0.10 but R_B^S − R_A^S < 0.05, loss exists and the 1500-char ledger does not recover it.

**Arms** (isolated worktrees, identical chain, identical model, identical `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=40`,
`--autocompact 200000`):
- **A vanilla** — no hooks.
- **B batch ledger** — D-037's `settings.arm_B.json` verbatim: `ledger.py` at PreCompact rebuilds the store from the
  transcript; `inject.py` at SessionStart(compact) only, `D037_BUDGET_CHARS=1500` written into the command by the
  driver (A9).
- Arm C (online loop) is **dropped** per D-037's conclusion line. Hook bundle `d037_hooks/` is reused byte-for-byte;
  its hashes are those in D-037's seal.

**Target.** `Wavex-Labs/wavex-experience-architect`, subtree `scripts/concierge-agent/`, pinned at commit
`ecbe2804d2832ea60825079cc047921525df2da6` (git tree `4443e8aa1bf89a19de19d9eaed008acd2616c4a0`). It is the always-on booking-intent listener: an HTTP server, a classifier, a
Claude-Agent-SDK runner, a QA corpus, a training routine (14 files copied; 1 365 lines across `.mjs`/`.py`/`.md`/
`.json`/`.plist`; `.plateau/`, `node_modules/`, `logs/`, `.env*` are never copied). The six ES modules
`server.mjs, agent.mjs, classify.mjs, qa.mjs, qa-corpus.mjs, train.mjs` play the role of D-037's `mod0..mod5`.
The repository is private: the driver copies the subtree from a local checkout into the worktree at run time; nothing
from it is written into this (public) tree — see "Raw-artifact policy" below, which is binding.

**Chain.** **N = 18** tasks (= 4m − 2 at the predicted compaction period m = 5, one more period than D-037's 13).
Every task begins "Read `concierge-agent/FIXTURE_k.md` fully" and writes that fixture's nonce to `nonce_k.txt`
(D-037 A5: read proof + ballast). Task k establishes one fact of kind `KINDS[(k−1) mod 3]` in
`FILES[(k−1) mod 6]` and three mandated exported helpers `h{k}_alpha/beta/gamma` (distractors):
- *constant* — a new exported module-level integer constant, UPPER_SNAKE_CASE, name chosen by the worker;
- *function* — a new exported function returning 7, name chosen by the worker;
- *module* — a new `<name>-util.mjs` exporting `ping()`, `<name>` chosen by the worker.

Task k > 3 additionally adds `export function link_k()` in a *use file* that (a) is never `classify.mjs`, (b) is not the
file edited in task k, (c) is not the file holding the task-(k−3) fact, and that returns / calls / imports the k−3 fact
"from your memory of the name you chose in task k−3, without re-reading `<dep file>`" (A13 wording). The use-file
rotation is deterministic (`gen_chain.py`). Every task ends "run `bash gate.sh` and make sure it passes".

**No name marker (registered change vs D-037).** D-037's facts carried suffixes (`_LIMIT`, `_handler`, `_util`) that a
compaction summarizer can key on. D-038 dictates only the kind; the scorer finds the fact by **snapshot diff**
(new exported integer constant / new exported non-mandated function / new `*-util.mjs` between snap k−1 and snap k).
This removes the salience cue and is one of two levers (with the real target) that could move λ̂ off zero. The two
levers are not separable in this design; D-038 tests whether loss appears at all, not which lever causes it.

**Gate.** `gate.sh` = `node --check` on every `.mjs` in the subtree + `node --test d038.test.mjs`, where the test
imports `classify.mjs` only and asserts its documented boat / car / manual contract. It is a real regression gate: a
task that breaks a module fails its gate. `classify.mjs` is excluded from the use-file rotation so that the gate never
transitively imports `server.mjs` (which exits without env) or `agent.mjs` (whose SDK import is not installed).

**Compaction is a controlled variable (A2–A4 re-instantiated).** θ = 72 000 tokens, residual r ≈ 36 k. Per-task growth
g = fixture read + real module reads (1–2 modules ≈ 2–5 k tokens) + tool overhead. Target g ≈ 7.2 k ⇒ m = 5 ⇒
boundaries predicted inside tasks 5, 10, 15 ⇒ design-predicted S = {6,7,8,11,12,13,16,17,18}, NS = {4,5,9,10,14,15}.
The fixture size (words) is **set by preflight pf1, not assumed**: D-037's realised period was 3 (boundaries at tasks
5/8/11 in 7 of 9 sessions) against a predicted 5, and at period 3 the NS set collapses to {4,5} and α̂ rests on two
items. pf1 therefore runs 6 tasks and must show no boundary before task 5; the size is lowered until it does.
A8 governs: the S/NS split is read from `compact_boundary` lines per run; the prediction is not assumed.

### Metrics and estimators (scored by a separate process, `score.py`, deterministic; every item cites transcript file + line)

Per arm and run, split dependent tasks into straddling (S) and non-straddling (NS) by the spec definition (boundary
in [k−3, k−1]); the A8 "effective" variant is reported beside it.
- R_X^S, R_X^NS = fraction of dependent tasks in each set where `link_k` is present, the use file parses
  (`node --check`), and the file references a name in the task-(k−3) fact set.
- α̂ = R_A^NS; λ̂ = 1 − R_A^S / α̂; π̂_B = 1 − (1 − R_B^S / α̂) / λ̂ (defined only when λ̂ > 0).
- tokens per task from transcript usage fields; re-derivations (target `.mjs` re-read after a compaction that was read
  before it); `dep_rereads` (counted, not failing, A13); nonce rate; injection chars ≤ budget (B).
- Resolution: |S| ≈ 9 and |NS| ≈ 6 per run, so one item moves R by 0.11 (S) or 0.17 (NS). λ̂ is coarse by design;
  bets are set one item wide.

### Pre-registered bets

| Bet | Statement | P |
|---|---|---|
| B1 | λ̂ ≥ 0.10 (native compaction loses at least one straddling fact beyond the NS baseline) | 0.45 |
| B2 | R_B^S − R_A^S ≥ 0.05 | 0.40 |
| B3 | λ̂ > 0 and π̂_B ≥ 0.5 (the ledger restores at least half of what native compaction loses) | 0.30 |
| B4 | tokens/task_B ≤ 1.05 × tokens/task_A | 0.65 |

3 runs per arm, seeds 1–3 (seed = run number, same seed for A and B). WIN = holds in ≥2 of 3; PARTIAL = holds in
exactly 2 of 3 with a holding run within 0.10 of its threshold (one item); LOSS otherwise (`score.py`).

**Pre-registered conclusion lines.**
- B1 LOSS ⇒ "native compaction does not lose worker-established names on a real ~1.4k-line subtree at N = 18 on
  CLI 2.1.273 / claude-sonnet-5; the ledger has no observed loss to recover; next iteration = scale the target
  (≥ 10 k lines, e.g. `supabase/functions`) or retire the compaction-loss line."
- B1 WIN, B2 LOSS ⇒ "loss exists; a 1500-char ledger at compaction does not recover it; next = budget sweep (6000)
  and ledger-content redesign, not a new mechanism."
- B1 WIN, B2 WIN ⇒ "ledger-at-compaction supported on a real target; next = adapter integration and a cost line."

### Raw-artifact policy (binding; new)

`aimerdoux/plateau` is public. Snapshots (`snap/k`), the worktree copy (`work/`), transcripts (Read output) and
`out_k.json` all carry the private target's source. Therefore:
- `experiments/d038/raw/` is **gitignored**. After each completed run `hash_raw.py` writes `raw_hashes.txt` (SHA-256 of
  every raw file), which **is** committed; the seal cites the target only by commit and tree hash.
- The operator archives `raw/` as one tarball outside this repo (the Wavex repo or private storage); its SHA-256 goes
  into the seal. Recompute (`score.py --raw`) is therefore verifiable by anyone holding the tarball, and the record
  says so where it reports results — it does not claim public recompute.
- Committed and target-free: `results.json` (worker-chosen identifiers, counts, transcript line numbers only),
  `chains/seed_s/` (fixtures, prompts, `gate.sh`, `d038.test.mjs`). The four assertions in `d038.test.mjs` are the only
  target-derived lines in this tree; they restate the classifier's documented car / boat / manual contract.
